# P36 — Response Projects

## Page contract

- Route: `/projects/responses`
- Archetype: project / milestone workbench
- Primary users: response programme manager, project owner
- Secondary users: Case, Problem, Change and Task owners; executive sponsor
- Primary decision: which response projects, milestones and outcome gates require intervention now?
- Primary action: create or update a project, milestone, blocker or outcome verification request
- High-risk action: complete/reopen a project or verify an outcome while linked ITSM evidence is incomplete

## Elastic/EUI visual direction

The page follows current Elastic product patterns without cloning an Alerts page:

- one top query/filter/action bar;
- compact semantic status and progress indicators;
- bordered `EuiPanel` modules separated by 24px major gaps;
- data-dense portfolio and milestone tables with explicit horizontal overflow handling;
- contextual Flyout that preserves the portfolio and selected project;
- impact Modal for outcome verification;
- text labels always accompany status colour;
- wrapping, minimum-width and responsive rules prevent clipped or overlapping content.

## First viewport

1. Portfolio/Milestones/Outcomes tabs with project search, status and risk filters.
2. Five decision KPIs from the project portfolio.
3. Response portfolio rail.
4. Selected project objective and milestone/dependency timeline.
5. Risk/outcome and linked-evidence side panels.

## Difference contract

P36 is not an ordinary queue:

1. The first viewport is a portfolio rail plus a selected-project milestone timeline, not a homogeneous work-item grid.
2. The main interaction is milestone/dependency/outcome verification, not assignment or status triage.
3. Linked Case, Incident, Problem, Change and Task objects remain evidence references; the project owns objective and success criteria.
4. The detail path uses project/milestone evidence and an independent outcome gate, not a generic row detail.

## Data and state boundary

- Candidate fields: `project_id`, `objective_scope`, `status_health`, `owner_team`, `milestones`, `work_items`, `linked_objects`, `risk_blockers`, `outcomes`, `timeline_audit`.
- Query scope: project ID/name, objective, owner, service, milestone, blocker and linked object.
- Prototype writes create queued receipts only.
- Closing linked ITSM work does not complete the project.
- Project completion requires independent, fresh outcome evidence.
