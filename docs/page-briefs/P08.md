## Core task

Resolve canonical asset identity, ownership, source provenance, freshness and exposure before pivoting to Asset 360, Device Status, Event Hunt or ITSM work. Source observations remain distinct from canonical assets and CMDB-owned fields are never silently overwritten.

## First viewport and main workspace

1. Asset search and facets for type, lifecycle/health, owner, inventory source and risk context.
2. Decision summary for active, unreconciled, stale, unowned-critical and high-exposure assets.
3. Source-coverage and blind-spot rail with exact values.
4. Dense canonical inventory table with identifiers, lifecycle/health, ownership, source reconciliation, last-seen and exposure.
5. Selected-asset identity preview with Asset 360, Device Status and Exposure pivots.
6. Asset Preview and Reconciliation Flyouts with field ownership, impact preview and prototype receipt.

## Difference contract: P08 versus P06 and P37

1. **First viewport:** P08 begins with asset identity search/facets, source coverage and a canonical inventory table; P06 begins with governed action lifecycle filters, while P37 begins with identity/account risk and access review.
2. **Primary workspace:** P08 centers canonical identity, identifiers, freshness, ownership and reconciliation; P06 centers approvals/receipts/rollback, while P37 centers MFA, groups and effective access.
3. **Primary interaction:** P08 searches, selects and reconciles source observations; P06 approves or recovers response actions, while P37 reviews identity lifecycle and access.
4. **Detail path:** P08 uses an Asset Preview plus Reconciliation Flyout and pivots to Asset 360/H15; P06 uses Action Detail/Approval, while P37 uses User Detail/Access Review.
