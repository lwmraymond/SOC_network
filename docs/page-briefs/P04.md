# P04 — Incidents & Cases

## Page brief

- Primary user: SOC analyst and case owner.
- Job story: prioritize active cases, inspect evidence/entities/tasks/response in one investigation context and form an auditable conclusion.
- First-screen questions:
  1. Which case should be handled next and why?
  2. What evidence, entities and gaps support the working conclusion?
  3. What action, approval or ITSM recovery information is still required before closure?
- Primary action: `Create case` through the existing prototype action/receipt boundary.
- Primary data surface: saved views + analyst queue + selected case investigation workspace with tabs and next-decision rail.
- KPI need: no generic KPI strip; priority and readiness are embedded in the case queue and selected case.
- Chart need: none on the first screen; evidence readiness uses exact bounded progress.
- Overlay: case preview flyout.

## Difference contract

- Archetype: analyst queue + case investigation workspace.
- Hero region: selected case header, evidence state and working hypothesis.
- First viewport regions: scope/saved views → analyst queue → case tabs/evidence → next decision.
- Primary action: create case.
- Detail type: case preview flyout plus in-page full investigation tabs.
- Must not copy: P17 Problem Management.

### Three required structural differences from P17

1. P04 starts with a live analyst queue and selected investigation; P17 starts with recurrence clusters and root-cause hypotheses.
2. P04's primary interactions are claim/assign, evidence collection, response request and ITSM incident linkage; P17 records RCA, workaround, known error and permanent fix.
3. P04 details use overview/timeline/evidence/entities/work/response/ITSM/audit tabs; P17 uses incidents/RCA/workaround/fix/review/audit.

## Shared-component risk decision

- Generic `MetricStrip`, `MiniChart`, `QuestionRail`, `PrototypeGrid` and `TimelinePanel` are not used.
- EUI queue, tabs, progress, flyout and status primitives support a page-specific investigation composition.
- Query state stores the selected case without changing the application Router architecture.
