# P05 — Alert Queue

## Page brief

- Primary user: SOC L1/L2 analyst.
- Job story: triage deduplicated alert groups, inspect why a rule matched and what evidence/entities are grouped, then assign, classify, create a case or preview suppression impact.
- First-screen questions:
  1. Which alert groups represent meaningful attack activity rather than duplicate noise?
  2. Why did the rule match and which exact events/entities support it?
  3. What future detection coverage changes if the group is closed or suppressed?
- Primary action: `Create case` through the existing prototype action/receipt boundary.
- Primary data surface: query/saved views → alert group triage queue → persistent evidence/rule preview → triage decision rail.
- KPI need: no reusable KPI strip. Four queue-health facts are embedded in the triage header.
- Chart need: no event histogram on the first screen; P07 owns raw-event histogram exploration. Group compression is shown with exact counts/progress.
- Overlay: alert group evidence flyout and suppression/triage impact modal.

## Difference contract

- Archetype: alert-group queue + evidence preview.
- Hero region: alert queue pressure and persistent selected-group evidence.
- First viewport regions: query/saved views → queue health → group table → evidence preview → triage decision.
- Primary action: create case.
- Detail type: grouped-evidence/rule-outcome flyout and suppression impact modal.
- Must not copy: P07 Event Search & Hunt.

### Three required structural differences from P07

1. P05 is queue-first around deduplicated alert groups; P07 is query-first around raw events and a time histogram.
2. P05 interactions select, assign, classify, link/create cases and preview suppression coverage; P07 interactions build a query, inspect one raw event and create an export job.
3. P05 detail explains rule outcome, group compression and future suppression impact; P07 detail is a raw event inspector plus export receipt.

## Shared-component risk decision

- Generic `MetricStrip`, `MiniChart`, `StatusStrip`, `QuestionRail` and `PrototypeGrid` are not used.
- Shared query, filter, Saved View, cursor, permission, action and receipt contracts are preserved because they are platform foundations, not a visual page skeleton.
- Suppression explicitly distinguishes selected-group closure from future matching behavior.
