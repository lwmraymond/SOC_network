# P01 — Security Operations Overview

## Spec extraction

- Primary user: SOC shift lead; L2/L3 analyst.
- Job story: identify the highest-risk unassigned security work, its evidence and entity contributors, and source gaps within the current scope.
- First-screen questions:
  1. What is the most dangerous unassigned work now?
  2. Which evidence and entities support the risk conclusion?
  3. Which missing sources make the conclusion unreliable?
- Primary action: `Create case`.
- Required summary: Confirmed attacks, High-risk unassigned, SLA at risk, High-risk entities, Required-source coverage.
- Primary data surface: security command canvas with ranked attention board, evidence confidence, coverage, workload and source integrity.
- Overlay: work-item preview and create-case flow.
- Required states: loading, empty, filtered-empty, error, denied, offline, stale, degraded and partial.

## Differentiation contract

- Archetype: Operational Dashboard + Attention Queue.
- Hero region: scope/search/filter command bar followed by a decision summary, not a decorative chart wall.
- First viewport: normalized scope controls; five decision metrics; ranked critical attention board; attack coverage and analyst workload context.
- Primary interaction: narrow the operational scope and open/create a case from ranked work.
- Detail/workflow: work-item triage and create-case simulation.
- Most similar page to avoid copying: P13 ITSM Overview.

### Required structural differences from P13

1. P01 prioritizes security work by risk/evidence/SLA; P13 organizes service operations by service health and typed ITSM work.
2. P01 centers an attention board plus attack coverage; P13 centers SLA lanes, service health, change windows and synchronization conflicts.
3. P01's primary action is Create case; P13's actions route to incident/request/change queues and service coordination.

## Shared-component risk decision

- `MetricStrip`: not used; the five required metrics are presented as a page-specific shift decision summary.
- `MiniChart`: not used as a generic dual-chart pattern.
- `PrototypeGrid`: not used as the page skeleton.
- `QuestionRail`, `StatusStrip`, `TimelinePanel`, `SettingsBoard`, `CatalogBoard`: not used.
- `SecurityCommandCanvas`: accepted because it is P01-specific and contains security-domain regions rather than a reusable universal page skeleton.
