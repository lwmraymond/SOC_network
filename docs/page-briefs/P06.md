## Core task

Show response requests as a governed lifecycle: request → approval → execution → authoritative external state → immutable receipt → optional rollback/recovery. Queued or accepted must never be presented as completed.

## First viewport and main workspace

1. Search, approval state, execution state and risk filters with saved views.
2. Governed action queue organized by risk, action type, target, case and lifecycle state.
3. Selected-action governance workspace with approval, policy expiry, impact preconditions and tabs for attempts, receipts and rollback.
4. Authoritative external-state and recovery lane.
5. Action detail Flyout and approval Modal.

## Difference contract: P06 versus P25

1. **First viewport:** P06 begins with governed action status filters and an approval/external-state queue; P25 begins with a task dispatch pipeline and agent capacity.
2. **Primary workspace:** P06 centers request governance, policy expiry, receipts and rollback; P25 centers target dispatch, eligible agent capacity and task execution throughput.
3. **Primary interaction:** P06 supports approve/decline/cancel/retry/rollback/escalation; P25 supports dispatching tasks to eligible agents and monitoring task execution.
4. **Detail path:** P06 uses an action detail Flyout plus approval Modal; P25 uses task/agent execution context and receipt stream.
