# P03 — Platform Health

## Page brief

- Primary user: platform SRE and SOC platform operator.
- Job story: follow the source → pipeline → queue → service dependency chain to locate latency, loss or degradation and explain affected security capabilities.
- First-screen questions:
  1. Which capability is currently unavailable or untrustworthy?
  2. Where did the failure begin, what is affected downstream and what changed recently?
  3. Should the operator create an incident, pause ingestion, scale workers or prepare rollback?
- Primary action: `Create platform incident` through the existing prototype action/receipt boundary.
- Primary data surface: active degradation chain, queue/source telemetry, affected capabilities and recovery action queue.
- KPI need: no generic KPI strip; only operational telemetry with explicit budgets.
- Chart need: no decorative chart. Progress indicators communicate bounded lag, age and error telemetry.
- Workflows: H11 service logs, H12 runtime queues and H13 connectors remain parent-owned routes.
- Overlay: page-specific health issue diagnostic flyout.

## Difference contract

- Archetype: operational health workbench.
- Hero region: source-to-capability degradation chain with likely failure origin.
- First viewport regions: scope controls → dependency path → recovery decision → bounded telemetry.
- Primary action: create platform incident.
- Detail type: health issue diagnostic flyout and parent-owned service/queue/connector workflows.
- Must not copy: P01 Security Operations Overview or P13 ITSM Overview.

### Three required structural differences

1. P03 centers a dependency path and failure origin; P01 centers ranked security attention and P13 centers service/SLA operations.
2. P03's primary surface is runtime telemetry and recovery readiness; P01's is security triage and P13's is typed ITSM work coordination.
3. P03 navigates into logs, queue health and connector diagnostics; P01 creates/investigates cases and P13 opens incident/change/request queues.

## Shared-component risk decision

- Generic `MetricStrip`, `MiniChart`, `QuestionRail`, `PrototypeGrid`, `RelationshipMap` and `StatusStrip` are not used.
- Existing EUI primitives and `ParentWorkflowLinks` are reused without adopting a universal page skeleton.
- Recovery actions are explicitly marked as simulation and never presented as production completion.
